# Spec to Screen

A 55-second launch film for Anikit Video, at 1920×1080 and 60 fps, made only from an anikit-video spec. It's self-referential: a JSON spec types itself into a code block, each finished line "compiles" into the stage beside it, and the camera then pushes into the stage, which becomes the next shot frame for frame.

| Time | Shot | Components |
|---|---|---|
| 0:00 | "This film / is a JSON file." | kinetic `mask` text, `dots`, `grain` |
| 0:04.5 | The spec types itself, and the stage builds line by line | `code` (typing, line highlights), `aurora`, `globe`, `grid`; scaled group as the stage; camera push-in |
| 0:15.5 | Spec to Screen, full frame | the same layers at full size |
| 0:19.5 | Write it. / Check it. / Render it. / No browser. | kinetic `mask`/`blur` type with real CLI commands |
| 0:27.5 | Product shots, generated | `laptop` (dashboard screen), `phone` (chat screen), `bokeh`, `badge` |
| 0:35 | "This 55-second film rendered in N s" | `counter`, `progress-bar` |
| 0:39 | End-to-end wall time vs Remotion and HyperFrames, 20× | `bar-chart`, `counter` |
| 0:43.5 | JSON in. / Film out. | `particleText` |
| 0:47 | Chrome ANIKIT logo with a lens-flare sweep | `text-3d`, `lensFlare`, `godRays` |

Every cut lands on a beat of the 120 BPM score.

## Files

- `spec.json` is the film. It is generated by `build.py`, which mirrors the code block's deterministic typing rhythm so that each stage event lands on the exact frame where its line finishes typing.
- `music.mp3` is the score, synthesised by `music.py` (numpy additive synthesis, then ffmpeg/libmp3lame).
- `poster.png` is the frame at 0:52.5.

The film also relies on an engine fix: `SharedAssets::image` no longer holds its lock while building an image, since text-3d's parallel build could deadlock the render.

```sh
python3 examples/video/spec-to-screen/music.py    # optional: regenerates music.mp3
python3 examples/video/spec-to-screen/build.py    # optional: regenerates spec.json
cargo build --release -p anikit-video
target/release/anikit-video render examples/video/spec-to-screen/spec.json -o spec-to-screen.mp4
```

## Render

Measured on a 4-core cloud VM (Xeon, AVX2) with `--json` and the default ak264 encoder:

| Output | Frames | Wall time | Render fps | File size |
|---|---|---|---|---|
| 1920×1080, 60 fps, H.264 + AAC, 55 s | 3300 | 21.5–24.8 s (2 runs, engine at 596aea8) | 133–153 fps | 29.0 MB |

That is about 1.8× faster than real time, end to end, including the chrome text-3d, the globe and the particle text.

The spec is designed to keep renders fast and files small. The film grain is static, the aurora steps at 4 Hz, every camera move is a punch of 0.5 s or less that then holds, and the logo holds its final pose for the last 3 s. Held frames are nearly free for both the renderer and ak264. The "rendered in" stat in the film is `RENDER_SECONDS` in `build.py`: re-measure and update it after an engine change.

## The numbers in the film

Every figure is measured:

- **"Rendered in N s":** this film's own end-to-end wall time. `RENDER_SECONDS` in `build.py` is set from the final measured render on the release machine (machines vary: 21.5–24.8 s here, 43.9 s on another 4-core VM).
- **Bar chart and 20×:** `docs/video/BENCHMARKS.md`, composition (d), 60 s of 1080p60 kinetic type, default settings, median of 3 on a 4 vCPU Xeon. Anikit Video takes 6.95 s, Remotion 139.5 s and HyperFrames 152.0 s. 139.5 ÷ 6.95 = 20.1.
